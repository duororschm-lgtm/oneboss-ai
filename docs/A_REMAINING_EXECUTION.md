# A组剩余任务执行记录

## A-01 请求可靠性与中断清理

2026-11-07完成代码与本机验证：87项单元、34项PostgreSQL集成、类型检查及生产构建通过。线上验证另行记录，不能仅凭本机结果宣称内存问题已解决。

- Render Events明确记录实例`45tdt`于20:49因超过512MB内存限制失败；日志20:49:38显示重启，20:50恢复。19:30另有HTTP健康检查5秒超时事件。
- 历史验收没有保留失败请求ID或HTTP状态，因此无法确定每次非JSON响应的来源，也不能把所有中断都归因为内存超限。
- 发布浏览器现在复用同一个context/page依次检查三个宽度，限制renderer数量并关闭GPU；不放宽沙箱、TLS或验收门禁。是否消除内存超限需A-02实际观察。
- 操作脚本遇到网络/超时/非JSON响应最多3次，等待1秒、2秒，每次最多90秒；同一写操作保持请求体和幂等键。结构化业务拒绝不自动重试。追踪仅含状态和请求标识，不包含响应正文、令牌或密码。
- 开始创建Auth身份前写入`.secrets/acceptance/hosted-write.json`，后续记录组织、项目、操作键与任务；新验收拒绝覆盖尚未清理的检查点。
- 中断后选择安全清理，而非从头重新生成模型：先验证邮箱、用途、随机nonce、Auth身份和组织所有权；撤销临时演示权益、停止排队任务，最多等待运行中任务15分钟，之后清理专属Storage、业务记录和Auth。超时保留检查点，明确报错，不在活跃任务下删数据。

清理已有检查点（不会创建订单或调用模型）：

```powershell
$env:RUN_HOSTED_WRITE_ACCEPTANCE='true'
$env:CLEANUP_HOSTED_ACCEPTANCE='true'
$env:DATABASE_HTTP_PROXY='http://127.0.0.1:10808' # 仅本机确实使用此代理时
node --env-file=.env.local --import tsx scripts/acceptance-hosted-write.ts
```

清理成功后检查点归档并移除其中的密码；清理结果单独写入`cleanup-recovery.json`，不会覆盖原验收结果。运行新验收前移除`CLEANUP_HOSTED_ACCEPTANCE`环境变量。不要手工删除活跃检查点来绕过保护。
