## 每个目标完成后的GitHub同步

按用户要求，每完成一个可验收目标（例如A-01），立即执行以下流程，不等全部任务结束才上传：

1. 依据该目标的完成条件检查结果，运行相关测试；未通过时继续修复，不能标记完成。
2. 更新任务状态、验证证据和剩余问题；仅暂存该目标涉及的源码、文档及允许公开的证据。密钥、环境配置、业务备份和临时客户数据不进入Git。
3. 为该目标创建独立commit，推送当前工作分支`feat/core`到GitHub；不自动合并`main`，不覆盖其他人的提交。
4. 检查远端提交并报告目标编号、commit链接、验证结果及CI状态。若推送或CI失败，明确报告并处理，不声称同步成功。
5. 网站上线单独记录：push仅代表GitHub代码已同步。需要发布时完成部署，核对部署commit并验证线上功能，之后才报告“已上线”。

此规则适用于当前授权任务的执行过程，不创建后台定时上传任务，也不保证聊天停止后继续执行。
