# 账号密码注册与登录

普通客户注册只填写账号和密码，不填写邮箱、不接收验证码。注册完成后直接进入工作台。原有邮箱账户继续使用完整邮箱和原密码登录，管理员权限仍由平台授权决定。

## 客户使用

1. 打开 /login，选择“还没有账户？注册”。
2. 设置账号（3–32位中文、字母、数字或下划线）与密码（10–128位）。账号不区分英文字母大小写，全角字符会规范化；相同规范化账号不能重复注册。
3. 点击“创建账户”进入工作台。刷新后会保留登录状态，退出后可以用同一账号密码登录。

注册不会自动开通付费制作权益，也不会获得审核后台权限。密码遗忘暂时需要联系客服；邮件找回仅面向原邮箱账户，仍需完成邮件服务配置。

## 实现与运营

- 新注册入口：POST /api/auth/register，只接受 username/password，拒绝额外角色、权限等字段。
- 认证仍由既有 Supabase Auth 处理，业务数据库不保存密码。账号映射到保留的非投递命名空间，不声称用户已验证某个真实邮箱；不修改 Supabase 的全局邮箱确认设置。
- 服务端使用既有私密凭据创建普通认证账户，不返回服务端密钥或高权限会话。客户端以实际密码登录得到原有 Auth 会话，租户与平台审核权限检查继续有效。
- 新入口复用私有 rate_limits 表：全局20次/分钟与100次/小时，网络提示10次/小时，单账号5次/小时。网络头仅用于防滥用提示，全局预算不依赖其可信度；数据库只保存HMAC键及计数。
- 未增加支付权限、组织权限或真实邮箱注册接口。旧邮箱管理员和客户账户不需要迁移、改密或重新注册。
- 本机验收：TEST_DATABASE_URL 指向空的 oneboss_acceptance_ 前缀本地库，运行 node --env-file=.env.local --import tsx scripts/acceptance-registration.ts。
- 线上只创建临时 Auth 账户、不创建组织/订单/模型任务：RUN_HOSTED_REGISTRATION_ACCEPTANCE=true 后运行同一脚本，结束会按准确身份清理测试账户。
