# 业务备份与隔离恢复

此工具按需备份应用的27张业务表、迁移账本和数据库引用的私有Storage文件。使用PostgreSQL只读可重复读快照；文件逐项校验并重复下载确认未变。数据库一致性以快照时点为准；不要求其他客户停止使用服务。

备份包含组织/成员/管理员关联、订单、权限、事实、版本、任务和交付等敏感业务数据。**不包含Supabase Auth密码、会话、商户密钥、模型密钥或整个Supabase平台配置**，不能称为完整平台灾难恢复。恢复中的Auth函数仅用于本地权限演练，不提供客户真实登录。

## 保存位置

- 加密档案：`.cache/business-backups/<备份编号>.oneboss`，AES-256-GCM，随机256位密钥、96位随机nonce和认证标签。
- 单独密钥：`.secrets/backup-keys/<备份编号>.key`。不写入档案、日志或Git；应与档案分开保管。
- 备份摘要：同目录的`<备份编号>.json`，仅包含数量、档案哈希和状态。
- 恢复文件与结果：`.cache/restore/<隔离库名>/`。恢复后的文件为明文业务数据，仍需私下保管。

以上目录均被Git和Docker忽略。第一阶段只有本机副本，没有定时备份或异地容灾承诺；不要删除唯一密钥，否则无法解密。工具不会自动删除旧备份。

## 创建备份

在项目根目录使用本机已有私下配置，不在命令行粘贴密钥：

```powershell
$env:RUN_BUSINESS_BACKUP='true'
$env:DATABASE_HTTP_PROXY='http://127.0.0.1:10808' # 仅本机实际需要时设置
node --env-file=.env.local --import tsx scripts/business-backup.ts create
```

输出`passed:true`仅代表加密备份及内部完整性检查成功，尚不代表恢复成功。发现未知public表、迁移版本不匹配、引用文件缺失、文件变化或文件哈希不符时拒绝生成成功备份。失败后排查原因，再完整重做。

## 隔离恢复

先在本机127.0.0.1:55432创建一个**全新空数据库**，名称必须以`oneboss_restore_`开头。然后：

```powershell
$env:RUN_BUSINESS_RESTORE='true'
$env:RESTORE_DATABASE_URL='postgres://postgres@127.0.0.1:55432/oneboss_restore_新的唯一名称'
node --env-file=.env.local --import tsx scripts/business-backup.ts restore <备份编号>
```

恢复工具只连接上述本机端口；拒绝远程主机、其他库名、URL查询参数及非空库，不删除已有业务表。恢复使用仓库内与备份账本哈希一致的可信迁移，不执行备份中附带的SQL。保留原ID、时间精度、JSON内容和引用关系，逐表逐行比较，再检查恢复文件哈希和成员/陌生用户的RLS读取边界。

不会启动HTTP服务、worker、模型或支付调用，也不会向生产Storage回写。恢复失败后保留隔离现场；先核对失败原因，使用另一个全新库名重试。生产环境回迁需要单独的维护方案，不使用此命令绕过目标限制。
