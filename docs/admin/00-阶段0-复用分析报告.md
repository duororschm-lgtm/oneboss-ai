## 2. 路由现状

```
src/app/

  api/[...path]/route.ts 唯一后端入口（catch-all，515 行）
  p/[slug]/              已发布站点
  preview/[projectId]/   草稿预览
```

- **没有 `/admin` 路由**，需要全新建立。
- `/dashboard/admin` 已存在，是**客户工作台里的一块页面**（`src/components/customer/admin.tsx`），不是独立后台。

## 3. 认证与权限（关键发现）

| 项 | 实际实现 | 影响 |
| --- | --- | --- |
| 身份 | `authenticate(request)` 校验 Supabase JWT，返回 `actor.userId` | 可复用 |
| 平台管理员 | 表 `platform_admins(user_id uuid primary key)` —— **只有 user_id，没有角色列** | **RBAC 不存在**，任务书要求的 owner/finance/operations/reviewer 四角色后端无支撑 |
| 租户 | `organizations` + `memberships(role: owner/admin/member)` | 这是**客户侧**角色，与管理员角色无关 |
| 管理员数据入口 | `GET /api/core/admin` → `adminWorkspace()`，先 `platformAdmin()` 校验 | 唯一可用的管理员接口 |
| 前端权限 | `accountWorkspace()` 返回 `isAdmin` 布尔 | 只能判"是不是管理员"，判不了"是哪类管理员" |

**结论：角色化权限（角色菜单、按角色隐藏按钮）无法真实实现**，只能做到"平台管理员 / 非管理员"二分。已列入缺口清单（A-07）。

## 4. 后端接口现状

`src/app/api/[...path]/route.ts` 是唯一入口，**没有 `/api/admin/*` 任何路由**。

现有与管理员相关的能力全部挤在一个接口里：

```http
GET  /api/core/admin                      # 订单100条 + 退款100条 + 待人工核验的收款
POST /api/commerce/orders/:id/confirm-manual
POST /api/commerce/orders/:id/finalize-refund
POST /api/commerce/orders/:id/refunds
```

`adminWorkspace()` 返回的三段数据（`src/lib/core/workspace.ts:18-28`）：

| 键 | 内容 | 可用于 |
| --- | --- | --- |
| `orders` | 订单号、组织名、套餐名、金额、付款状态、是否演示、创建时间 | 订单列表（真实） |
| `refunds` | 退款单、订单号、金额、状态、核验参考 | 退款队列（真实） |
| `manualAttempts` | 待核验的人工收款 + 客户提交说明 | 支付核验队列（真实） |

**没有**：分页、日期筛选、聚合统计、Agent 运行列表、作品审核列表、客户列表、审计日志。全部列入缺口。

## 7. 风险与边界

1. **最大风险是不小心把后台做成"第二套后端"**。本方案严格只加前端 + adapter，一行数据库读逻辑都不新增。
2. `/api/core/admin` 一次拉 100 条、无分页无筛选，数据量上来会拖慢；后台先在前端做展示层筛选，分页交 A 补接口。
3. `agent_runs` 已有数据但无管理员出口。**不得**在前端假装有监控数据；页面必须显示"接口未提供"。
4. 客户平台的 `ob-*` 样式与后台 `ad-*` 样式完全隔离，改动不会互相影响。
5. 现有 `/dashboard/admin` **保持原样不动**，避免破坏正在使用的审核流程；新后台通过链接跳转，不替换它。

---

## 8. 三条结论

1. **能真实做出来的**：订单列表、退款队列、人工支付核验、退款核验（4 项，全部基于现有 `/api/core/admin` 与现有写接口）。
2. **只能做出界面 + 空状态的**：经营总览聚合指标、收入趋势、Agent 监控、作品审核、客户、套餐、审计日志（7 项，等 A 补接口）。
3. **结构性缺失**：管理员角色体系（RBAC）后端不存在，四角色模型无法落地。

> **更新（2026-11-08）**：客户工作台里内嵌的旧审核页 /dashboard/admin 已下线（删除 src/components/customer/admin.tsx），旧链接自动跳转 /admin。管理员入口现在只有 /admin 一个。
