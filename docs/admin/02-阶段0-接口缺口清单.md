# 阶段 0-C｜A 组后端接口缺口清单

> 交接对象：A 组（后端）。以下每一条都是**管理员平台已经做出界面、但拿不到真实数据**的地方。
> B 不会自行实现这些接口，也不会用假数据冒充。

现状：唯一可用的管理员接口是 `GET /api/core/admin`，一次返回 `orders` / `refunds` / `manualAttempts` 各 100 条，无分页、无筛选、无聚合。

---

## P0｜挡住六个核心模块的缺口

### A-01　经营总览聚合接口

```http
GET /api/admin/dashboard?from=YYYY-MM-DD&to=YYYY-MM-DD
```

需要的字段：今日确认到账、本月净收款、累计订单数、待支付核验数、待制作放行数、制作中项目数、待作品审核数、待退款处理数、最近订单（10 条）、待办审批（10 条）、Agent 异常摘要。

当前状态：**完全缺失**。前端页面已实现，指标卡显示"接口未提供"。

---

### A-02　收入统计接口

```http
GET /api/admin/revenue?from=&to=&groupBy=day|week|month
```

需要：按日聚合的 `{ date, confirmedMinor, refundedMinor, netMinor, orderCount }`。

口径必须由后端给出（任务书 §2.3）：

| 指标 | 后端必须保证 |
| --- | --- |
| 订单总额 | 已创建订单应付金额总和，**不含**到账语义 |
| 已确认到账 | 渠道可信确认或授权人工核验成功 |
| 已成功退款 | 渠道已确认完成的退款 |
| 净收款 | 到账 − 成功退款 |
| 制作中订单金额 | 履约中，不计入收入 |
| 估算经营结余 | 仅参考，不得称利润 |

当前状态：**完全缺失**。B 不在前端做汇总（任务书明确禁止前端自行汇总财务金额）。

---

### A-03　订单分页与筛选

```http
GET /api/admin/orders?page=1&pageSize=20&keyword=&payState=&planCode=&from=&to=
```

返回 `{ items, page, pageSize, total, hasNextPage }`。

当前状态：`/api/core/admin` 只有 `limit 100`、无筛选、无 `project_id` 与制作状态关联。

补充字段需求：`work_state`（project 状态）、`paid_at`、`refunded_minor`。

---

### A-04　订单详情

```http
GET /api/admin/orders/:orderId
```

需要：订单主体、套餐权益快照、客户资料（脱敏）、支付记录、制作任务、网站/海报版本、客户修改请求、审批历史、退款记录、操作日志。

当前状态：**缺失**。现有 `/api/commerce/orders/:id` 是**租户作用域**接口，管理员无法跨租户读取。

---

### A-05　审批队列与动作

```http
GET  /api/admin/approvals?type=&status=&page=1
POST /api/admin/approvals/:approvalId/approve
POST /api/admin/approvals/:approvalId/reject
POST /api/admin/orders/:orderId/production-release
POST /api/admin/orders/:orderId/hold
```

当前状态：**部分存在**。只有人工收款核验（`confirm-manual`）与退款核验（`finalize-refund`）两个真实动作；**制作放行（production-release）、暂缓（hold）、要求补充资料、转交处理全部缺失**。

> 注：现有 `confirm-manual` / `finalize-refund` 前端已接通，可真实操作。

---

### A-06　Agent 运行监控

```http
GET /api/admin/agents/runs?page=1&pageSize=20&status=&role=
```

需要：8 个角色的运行记录、状态、任务编号、项目、起止时间、模型名、token、成本、错误摘要。

当前状态：`agent_runs` **表里已有数据**（`role`、`status`、`attempt`、`usage`、`error_class`、`completed_at`），但**没有管理员出口**，只有 `GET /api/core/runs/:id`（租户内）。缺口仅在于"加一个跨租户只读列表接口"。

---

### A-07　管理员角色体系（RBAC）

```sql
alter table platform_admins add column role text not null default 'owner'
  check (role in ('owner','finance','operations','reviewer'));
```

任务书 §3 要求四角色矩阵。当前 `platform_admins` **只有 `user_id` 一列**，后端无法区分财务管理员与内容审核员。

**这是结构性缺口**：在补齐前，B 只能实现"是/不是管理员"的二分权限，角色化的菜单与按钮隐藏无法真实生效。

---

### A-08　作品审核

```http
GET  /api/admin/works/reviews?page=1&pageSize=20&status=
POST /api/admin/works/:workId/review
```

需要：网站预览/正式 URL、海报 PNG 与尺寸、二维码目标 URL 与检测结果、小红书文案、商品名与价格、版本号、自动质检结果、客户确认状态。

当前状态：`artifact_versions` 有版本与状态，但**无跨租户只读接口，也无审核动作接口**。

---

## P1｜不挡住 P0，但影响完整体验

| 编号 | 接口 | 用途 |

| A-09 | `GET /api/admin/customers?page=` | 客户管理 |

---

## 安全要求（B 侧已遵守，A 侧需保证）

1. 所有 `/api/admin/*` 必须在服务端做 `platform_admins` 校验，**不能只靠前端隐藏菜单**。
2. 跨租户读取必须显式授权，不得沿用租户作用域的 `service.order()`。
3. 所有写操作必须落审计（`admin_audit_logs`：操作者、时间、目标、动作、结果、原因）。
4. 金额统一返回整数分，前端只做格式化。

---

## B 侧的应对（不绕过、不伪造）

- 有接口的：真实对接（订单列表、退款队列、人工核验、退款核验）。
- 无接口的：页面完整实现，数据区显示 **"后端接口未提供：`GET /api/admin/xxx`"**，并附上本清单编号。
- 开发演示：仅在 `NEXT_PUBLIC_ADMIN_MODE=mock` 时加载模拟数据，界面顶部常驻 **"开发模拟数据"** 横幅，生产环境默认 `live`。
