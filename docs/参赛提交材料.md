## 一句话

OneBoss 是一个能自主运转的 AI 创意交付组织：客户只提供产品资料，5 个 AI 员工分工完成创意方向、交互宣传网站、海报与文案，人类只在 4 个决策关口介入。

## 要解决的问题

小商家和独立品牌需要一套「能发朋友圈、能扫码、能讲清产品」的宣传物料，但：

- 找设计师做一套网站 + 海报 + 文案，报价 3000–8000 元，周期 2–3 周
- 用模板工具，出来的东西千篇一律，讲不出产品差异
- 用通用 AI 对话，得到的是散落的文案和图片，还要自己拼装

真正的痛点不是「生成一张图」，而是**从资料到可交付成品的完整流程**：谁定方向、谁写文案、谁做页面、谁验收、谁交付。

## 产品是什么

客户流程（4 步）：

1. 选套餐并下单（微信/支付宝，人工核验收款）
2. 填写产品资料、上传图片，确认需求简报
3. 从 2–3 套 AI 生成的设计方向里选一个
4. 点击生成，等待 2–5 分钟，拿到：交互宣传网站 + 海报（竖版/方版）+ 小红书文案 + ZIP 交付包

交付物是真实可用的：网站有独立公网地址和二维码，扫码即可访问。

## Agent 组织架构（必交项 5）

### 五个 AI 员工

| Agent | 职责 | 输入 → 输出 |
|---|---|---|
| **intake（资料分析）** | 把客户口语化的产品描述，提炼成「已核实事实」清单，判定哪些能对外说 | 客户输入 → 产品事实（含置信度与来源） |
| **design（创意总监）** | 基于事实与产品特征，生成 2–3 套互相区分的设计系统：配色、字体、版式、页面构图 | 事实 + 简报 → 多套方向 |
| **generate（制作）** | 按选定方向同时产出：网站结构与文案、海报规格、小红书文案 | 方向 + 事实 → 生产规格 |
| **publish（发布验收）** | 用真实 Chromium 打开成品，在 375/768/1280 三个宽度下验证页面可达、结构正确、交互真的能点 | 成品 → 验收证据 |
| **delivery（交付）** | 打包 ZIP、生成二维码、登记交付清单 | 成品 → 可交付物 |

### 协作与汇报关系

```
客户资料
   ↓
intake ──→ 事实清单（不可编造，价格/功效/认证必须来自客户）
   ↓
design ──→ 2–3 套方向 ──→ 【人工】客户选定
   ↓
generate ──→ 网站 + 海报 + 文案
   ↓
publish ──→ 浏览器验收（不合格就退回，不发布）
   ↓
delivery ──→ ZIP + 二维码 ──→ 【人工】客户验收
```

### 自主决策 vs 人工介入

**AI 自主决定（4 类）**

1. 产品事实的取舍：哪句话能说、哪句话是没依据的承诺
2. 设计方向本身：配色、字体、版式、页面结构，三套方案互相区分
3. 页面与文案的具体写法
4. 发布前的自我验收：不达标就不发布

**人工必须介入（4 个关口）**

1. 收款核验：AI 不碰钱，到账由人确认
2. 需求简报批准：客户确认交付范围
3. 设计方向选定：客户选，AI 不替代品味
4. 成品验收：客户确认，交付才算完成

这条分工线是产品的核心设计：**AI 负责「做得出来」，人负责「要不要」和「钱」。**
